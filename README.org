* Overview

** Problem

A Bunny DNS zone can contain records maintained by several projects and by
hand.  One project must be able to update its records without changing another
project's mail, verification, or service records.

** Solution

=bunnydns= lists and edits individual records, and reconciles project-owned
records from JSON.  Declarative records carry a stable ownership comment:

#+begin_example
managed-by:OWNER; key=KEY
#+end_example

The owner and key identify records across value and TTL changes.  =bunnydns=
does not create zones, alter delegation or DNSSEC, or prune records belonging
to another owner.

** How it works

1. Read a protected Bunny API key file.
2. Find one existing zone by its exact domain name.
3. Fetch every record through Bunny's official OpenAPI client.
4. Validate the requested direct change or build a declarative plan.
5. Before changing DNS, save a protected zone snapshot; afterward, fetch and
   verify the result.

** Quickstart

Install dependencies and run the read-only checks:

#+begin_src sh
gmake dependencies-status
gmake dependencies
./bunnydns
gmake self-check
./bunnydns list example.com
#+end_src

Direct commands use =$HOME/.secrets/bunnynet-api-key= by default.  To create
that file safely:

#+begin_src sh
./bunnydns init-key /absolute/path/to/bunnynet-api-key
#+end_src

The first direct change is explicit:

#+begin_src sh
  ./bunnydns add example.com A www 192.0.2.10
#+end_src

For repeatable reconciliation:

#+begin_src sh
  cp records.example.json records.json
  # Edit owner, zone, key_file, backup_dir, and records.
  ./bunnydns check records.json
  ./bunnydns plan records.json
  ./bunnydns apply records.json
  ./bunnydns verify records.json
#+end_src

* Why this script?

The [[https://github.com/BunnyWay/cli][official bunny.net CLI]] is the better
general-purpose tool for interactive Bunny operations, including DNS.
=bunnydns= does not replace it.  It handles one narrower job: safely
reconciling one project's records in a zone that also contains records
maintained by other projects or by hand.

Driving the official CLI from a wrapper could provide the same workflow, but
the wrapper would still have to implement and test these policies:

- Desired records live in one JSON file, with separate =plan=, =apply=, and
  =verify= stages.
- =managed-by:OWNER; key=KEY= gives each project-owned record a stable identity
  across value and TTL changes.
- =prune= removes only obsolete records owned by that project; it leaves other
  projects' and manually maintained records alone.
- Every write is preceded by a protected zone snapshot and followed by a fresh
  read and verification.
- The API key is read from a protected, non-symbolic file rather than from a
  command argument or environment variable.

The advantage is therefore the maintained policy layer, not another way to
call Bunny's API.  =bunnydns= uses Bunny's official OpenAPI client underneath.
If the official CLI gains equivalent ownership-aware reconciliation and
verification, using it directly would be simpler.

* Requirements

- POSIX =/bin/sh=, =stat=, =mktemp=, and ordinary POSIX utilities.
- jq 1.6 or newer.
- Node.js 18 or newer and npm.
- GNU Make is the bootstrap requirement for checks, dependency management,
  and installation; use =gmake= on SmartOS.
- An MD5 tool: =md5=, =md5sum=, =digest=, or =openssl=.
- Network access to =https://api.bunny.net= for online commands.

On a fresh SmartOS zone, install GNU Make once, then let the project manage
the rest of its toolchain.  pkgsrc lives under =/opt/tools= in the global zone
and =/opt/local= in a native zone:

#+begin_src sh
# Global zone
/opt/tools/bin/pkgin -y update
/opt/tools/bin/pkgin -y install gmake
/opt/tools/bin/gmake dependencies

# Native zone
/opt/local/bin/pkgin -y update
/opt/local/bin/pkgin -y install gmake
/opt/local/bin/gmake dependencies
#+end_src

* Installation

The workstation command is =bunnydns=.  The Node helper and packages are
internal runtime files.

#+begin_src sh
  gmake dependencies
  gmake show-install-paths
  gmake install
#+end_src

Default locations:

| Platform            | Command                    | Runtime                        | Manual                                  |
|---------------------+----------------------------+--------------------------------+-----------------------------------------|
| macOS               | =$HOME/bin/bunnydns=       | =$HOME/libexec/bunnydns=       | =$HOME/share/man/man1/bunnydns.1=       |
| SmartOS global zone | =/opt/custom/bin/bunnydns= | =/opt/custom/libexec/bunnydns= | =/opt/custom/share/man/man1/bunnydns.1= |
| SmartOS native zone | =/opt/local/bin/bunnydns=  | =/opt/local/libexec/bunnydns=  | =/opt/local/share/man/man1/bunnydns.1=  |
| Linux               | =/usr/local/bin/bunnydns=  | =/usr/local/libexec/bunnydns=  | =/usr/local/share/man/man1/bunnydns.1=  |

Use =gmake update= to install a missing copy or replace changed content.  It
compares the command, helper, dependency lockfile, and installed runtime.  An
identical installation is left untouched.

Absolute destination overrides are supported:

#+begin_src sh
gmake install \
  BINDIR=/usr/local/bin \
  LIBEXECDIR=/usr/local/libexec/bunnydns \
  MANDIR=/usr/local/share/man/man1
#+end_src

Set an absolute =DESTDIR= to stage an installation.  =gmake uninstall= removes
only files and package trees installed by this project; it preserves containing
directories.

* Dependency maintenance

Check for newer tools and known npm vulnerabilities without installing or
upgrading anything:

#+begin_src sh
gmake dependencies-status
#+end_src

The report shows installed tool versions, asks the platform package manager
what it would update from its current catalog, runs =npm outdated --all= to
show Current, Wanted, and Latest versions, and runs =npm audit=.  A stale
system-package catalog is refreshed by the installation action:

#+begin_src sh
gmake dependencies
#+end_src

That action installs or upgrades only the required system packages, then runs
=npm ci --ignore-scripts= so the JavaScript runtime exactly matches
=package-lock.json=.  It uses Homebrew on macOS, =pkgin= under =/opt/tools= or
=/opt/local= on SmartOS, and =apt-get=, =dnf=, =yum=, =apk=, or =zypper= on
Linux.  It finishes with the status report.

Advancing the reviewed JavaScript versions is deliberately separate:

#+begin_src sh
gmake dependencies-refresh
#+end_src

This updates every direct npm dependency to its registry =latest= version,
saves exact versions, rewrites the lockfile, and runs the complete test suite.
Review =package.json= and =package-lock.json= before committing.  On macOS or
Linux, =make= is also valid when it is GNU Make; SmartOS normally uses =gmake=.

* Commands

| Command                             | Effect                                                    |
|-------------------------------------+-----------------------------------------------------------|
| =bunnydns= or =bunnydns help=       | Print version and usage; change nothing.                  |
| =bunnydns version=                  | Print the release version.                                |
| =bunnydns list ZONE=                | List every record and numeric record ID.                  |
| =bunnydns list --records-file FILE= | Read the zone and key path from FILE, then list the zone. |
| =bunnydns add ZONE TYPE NAME VALUE= | Back up, add, fetch, and verify one record.               |
| =bunnydns update ZONE ID OPTIONS=   | Back up and change only the named fields.                 |
| =bunnydns delete ZONE ID=           | Back up, delete, verify, and print the deleted record.    |
| =bunnydns validate FILE=            | Validate local JSON without reading the key or network.   |
| =bunnydns check FILE=               | Validate dependencies, key protection, and API access.    |
| =bunnydns plan FILE=                | Print declarative actions without changing DNS.           |
| =bunnydns apply FILE=               | Apply a conflict-free plan and verify it.                 |
| =bunnydns verify FILE=              | Require all declared records to match.                    |
| =bunnydns prune FILE=               | Delete only obsolete records owned by FILE's owner.       |
| =bunnydns init-key KEYFILE=         | Securely create a mode-0600 API key file.                 |

Global =--api-key FILE= and =--backup-dir DIR= options must appear before the
command.  They accept absolute paths.

Direct =add= options are =--ttl=, =--priority=, =--weight=, =--port=,
=--flags=, =--tag=, =--disable=, and =--enable=.  =update= also accepts
=--type=, =--name=, and =--value=.  Use =@= for the zone apex.

Supported record types are A, AAAA, CNAME, TXT, MX, SRV, CAA, PTR, NS, SVCB,
HTTPS, and TLSA.

* Records file

=records.example.json= is the schema example.  The top-level object contains:

- =owner=: stable lowercase project namespace, up to 64 characters.
- =zone=: existing Bunny DNS zone.
- =key_file=: absolute path to the protected API key file.
- =backup_dir=: absolute path for pre-change snapshots.
- =records=: desired record array; an empty array is valid.

Each record requires a unique lowercase =key=, =type=, =name=, and non-empty
=value=.  Optional fields are =ttl=, =priority=, =weight=, =port=, =flags=,
=tag=, =disabled=, and =allow_multiple=.  TTL defaults to 60; numeric routing
fields default to zero.

Set =allow_multiple= only when a new value may join an unmanaged record set
with the same name and type.  It never bypasses CNAME exclusivity.

* Safety

- The key file must be regular, non-symbolic, mode 0400 or 0600, and contain
  one printable ASCII line.  The secret is never placed in an environment
  variable or process argument.
- Direct changes default to protected backups under
  =$HOME/.local/state/bunnydns/backups=.  Declarative changes use =backup_dir=.
- =apply= changes declared records only.  =prune= deletes only records whose
  comments match the declaration owner.
- Name or type changes use a backed-up delete-then-create replacement and may
  receive a new record ID.
- Do not run concurrent writers against the same zone during =apply= or
  =prune=.

* Development

#+begin_src sh
  npm ci --ignore-scripts
  gmake checksum
  gmake self-check
#+end_src

=bunnydns.md5= and =bunnydns-node.mjs.md5= detect accidental source changes.
MD5 is an equality check, not a signature.  npm verifies dependency downloads
using the integrity values in =package-lock.json=.

The offline suite covers direct changes, reconciliation, ownership isolation,
backups, post-change verification, installer paths, update/no-update behavior,
dependency-manager behavior, and macOS, SmartOS, and Linux branches without
changing a live DNS account or the host package database.

See =bunnydns(1)= for the complete command reference.
