* Overview

=bunnydns= edits records in a Bunny DNS zone and reconciles the records a
project declares in a JSON file, without touching anyone else's records.
Its interface follows SmartOS tools such as =vmadm= and =zfs=.

#+begin_example
bunnydns list [-H] [-o field,...] zone
bunnydns add zone type name value [property=value ...]
bunnydns update zone id property=value ...
bunnydns delete zone id
bunnydns apply [-n] [-f file]
bunnydns verify [-f file]
bunnydns prune [-n] [-f file]
bunnydns validate [-f file]
bunnydns init-key
bunnydns help | version
#+end_example

Declared records carry the Bunny comment =managed-by:OWNER; key=KEY=.  The
owner separates projects sharing a zone; the key follows a record through
name, type, value, and TTL changes.  =bunnydns= adopts only unmarked records,
treats another owner's or key's record as a conflict, and prunes only its
owner's undeclared records.  It never creates zones or changes delegation.

** Why we cannot use https://github.com/BunnyWay/cli directly

The official bunny.net CLI, =bunny=, is the general tool for Bunny: zones,
DNSSEC, record presets, storage, sites, and more.  On macOS and Linux it is
the better choice for one-off work.  =bunnydns= exists because of two gaps
in =bunny= 0.18.0 (2026-09-28):

- *It does not run on SmartOS.*  =bunny= is TypeScript built into standalone
  binaries with Bun, released only for macOS, Linux, and Windows.  Its npm
  package is a launcher that picks one of those binaries; on illumos, where
  Node reports the platform as =sunos-x64=, it exits with =Unsupported
  platform=.  The source cannot run under Node instead, because it uses
  Bun's own APIs, and Bun does not support illumos.  Neither the global zone
  nor a native zone can run it; only an LX-branded zone running the Linux
  binary might.  =bunnydns= needs only Python's standard library.
- *It edits records but does not reconcile them.*  Its DNS commands add,
  update, and remove one record at a time, and its BIND zone-file import
  only adds.  It cannot compare the records a project declares with the
  zone, mark records with an owner, refuse to overwrite another owner's
  records, delete only its own undeclared records, or preview all of that
  as a dry run.  That is the work of =apply=, =verify=, and =prune=.

Wrapping =bunny= would still leave the reconciliation to write, and would
still not run on SmartOS.  Revisit this if =bunny= gains illumos builds and
a declarative sync.

** Quickstart

Install, then store the Bunny API key; the prompt does not echo:

#+begin_src sh
gmake dependencies
gmake install
bunnydns init-key
#+end_src

Inspect and edit records by hand.  =update= and =delete= take the ID that
=list= shows, and every change first saves a snapshot of the zone (on
SmartOS in =/var/opt/scs/bunnydns/backups=; Settings below covers other
systems):

#+begin_example
$ bunnydns list example.com
ID     TYPE  NAME     TTL   DISABLED  VALUE
12344  TXT   @        3600  false     v=spf1 mx -all
12345  A     staging  60    false     192.0.2.20
12346  A     www      60    false     192.0.2.10

$ bunnydns add example.com MX @ mail.example.com priority=10
Backup: /var/opt/scs/bunnydns/backups/example.com-20261001T060146Z-s4ljfjad.json
Added record 12347 to example.com: MX @ mail.example.com

$ bunnydns update example.com 12345 ttl=300 disabled=true
Backup: /var/opt/scs/bunnydns/backups/example.com-20261001T060146Z-tk631l3r.json
Updated record 12345 in example.com: A staging 192.0.2.20

$ bunnydns list -o id,type,name,priority,value example.com
ID     TYPE  NAME     PRIORITY  VALUE
12344  TXT   @        0         v=spf1 mx -all
12347  MX    @        10        mail.example.com
12345  A     staging  0         192.0.2.20
12346  A     www      0         192.0.2.10
#+end_example

Declare a project's records in =records.json=:

#+begin_src json
{
  "owner": "example-project",
  "zone": "example.com",
  "records": [
    {"key": "web-origin", "type": "A", "name": "www", "value": "192.0.2.10"},
    {"key": "mail", "type": "MX", "name": "@", "value": "mail.example.com", "priority": 10},
    {"key": "api", "type": "A", "name": "api", "value": "192.0.2.11"}
  ]
}
#+end_src

Check the file offline, preview the plan, apply it, and verify:

#+begin_example
$ bunnydns validate -f records.json
records.json: 3 valid record(s) for example.com.

$ bunnydns apply -n -f records.json
UPDATE web-origin: A www 192.0.2.10 -- adopt the identical unmanaged record
UPDATE mail: MX @ mail.example.com -- adopt the identical unmanaged record
CREATE api: A api 192.0.2.11 -- no such record
3 change(s) would be made.

$ bunnydns apply < records.json
UPDATE web-origin: A www 192.0.2.10 -- adopt the identical unmanaged record
UPDATE mail: MX @ mail.example.com -- adopt the identical unmanaged record
CREATE api: A api 192.0.2.11 -- no such record
Backup: /var/opt/scs/bunnydns/backups/example.com-20261001T060146Z-gyb7n0nr.json
OK web-origin: A www 192.0.2.10 -- matches
OK mail: MX @ mail.example.com -- matches
OK api: A api 192.0.2.11 -- matches
Applied and verified 3 change(s).

$ bunnydns verify -f records.json
OK web-origin: A www 192.0.2.10 -- matches
OK mail: MX @ mail.example.com -- matches
OK api: A api 192.0.2.11 -- matches
All declared records match.
#+end_example

=apply= adopted the =www= and MX records made by hand by adding their
ownership comments, and created =api=.  The TXT and =staging= records are
not declared, so they were left alone.

Remove =api= from =records.json=, then delete it from the zone:

#+begin_example
$ bunnydns prune -n -f records.json
DELETE api: A api 192.0.2.11 -- no longer declared
1 record(s) would be deleted.

$ bunnydns prune -f records.json
DELETE api: A api 192.0.2.11 -- no longer declared
Backup: /var/opt/scs/bunnydns/backups/example.com-20261001T060146Z-6bs68kx8.json
Deleted and verified 1 record(s).
#+end_example

* Requirements

- Python 3.9 or newer, standard library only; 3.14 is the default.
- GNU Make and an MD5 tool (=md5=, =md5sum=, =digest=, or =openssl=) to check
  and install; =shellcheck= and =mandoc= are used when present.
- HTTPS access to =https://api.bunny.net=.

* Installation

On SmartOS, keep the checkout in =/opt/scs/src/bunnydns= and run these as
root:

#+begin_src sh
gmake dependencies     # install Python 3.14 and GNU Make if missing
gmake show-install-paths
gmake install
bunnydns init-key
#+end_src

| System             | Command                    | Manual                                 |
|--------------------+----------------------------+----------------------------------------|
| SmartOS (any zone) | =/opt/scs/sbin/bunnydns=   | =/opt/scs/man/man8/bunnydns.8=         |
| macOS              | =~/.local/bin/bunnydns=    | =$XDG_DATA_HOME/man/man8/bunnydns.8=   |
| Linux              | =/usr/local/sbin/bunnydns= | =/usr/local/share/man/man8/bunnydns.8= |

The installed command is =bunnydns.py= with its =#!= line set to the Python
found at install time (=python3.14=, else a =python3= that is 3.9 or newer;
=pkgsrc= directories are searched too), so cron and zones with another =PATH=
run the same interpreter.  Override with =PYTHON=/absolute/path=, and the
destinations with absolute =BINDIR=, =MANDIR=, and =DESTDIR=.

=gmake install= and =gmake update= warn when the command's directory is not
on =PATH=, or the manual's is not on a set =MANPATH=.  The stock root profile
in the SmartOS global zone has neither =/opt/scs/sbin= nor =/opt/scs/man=,
so add them to root's shell startup.

=gmake update= replaces the command or manual only when its MD5 differs.
=gmake uninstall= removes both and keeps settings and backups.

=gmake dependencies-status= reports the tools and any missing packages
without changing anything.  =gmake dependencies= installs only the missing
packages and never upgrades installed ones, because an upgrade can carry
unrelated packages along; upgrades are the host's own routine.  It uses
=pkgin= on SmartOS (=python314=, =gmake=, =mozilla-rootcerts-openssl=),
Homebrew on macOS (=python@3.14=, =make=), and =apt-get=, =dnf=, =yum=,
=apk=, or =zypper= on Linux.  On SmartOS, =pkgin= shows everything it would
change and asks before installing.  On a fresh SmartOS zone, install =gmake=
with =pkgin= first.

* Settings

| System          | Settings                                  | API key                             | Backups                            |
|-----------------+-------------------------------------------+-------------------------------------+------------------------------------|
| SmartOS         | =/var/opt/scs/bunnydns/bunnydns.conf=     | =/var/opt/scs/bunnydns/api-key=     | =/var/opt/scs/bunnydns/backups=    |
| Elsewhere (XDG) | =$XDG_CONFIG_HOME/bunnydns/bunnydns.conf= | =$XDG_CONFIG_HOME/bunnydns/api-key= | =$XDG_STATE_HOME/bunnydns/backups= |

On SmartOS, the program lives in =/opt/scs= and everything the host owns in
=/var/opt/scs/bunnydns=, following illumos's split between =/opt= and
=/var/opt=; =/etc= does not survive a reboot in the global zone.  =gmake
install= creates that directory with mode 0700 and never changes what is in
it.

The settings file is optional.  It holds =name=value= lines and =#=
comments; =key_file= defaults to =api-key= beside it and =backup_dir= to the
state directory's =backups=.  =bunnydns help= shows the paths in use.

#+begin_example
key_file=/var/opt/scs/bunnydns/api-key
backup_dir=/var/opt/scs/bunnydns/backups
#+end_example

* Records file

#+begin_src json
{
  "owner": "example-project",
  "zone": "example.com",
  "records": [
    {"key": "web-origin", "type": "A", "name": "www", "value": "192.0.2.10"},
    {"key": "mail", "type": "MX", "name": "@", "value": "mail.example.com", "priority": 10}
  ]
}
#+end_src

Each record has a unique lowercase =key=, the required =type=, =name= (=@=
for the apex), and =value=, and optionally =ttl= (default 60), =priority=,
=weight=, =port=, =flags=, =tag=, =disabled=, and =allow_multiple=.  The same
property names work on the command line: =bunnydns update example.com 12345
ttl=300 disabled=true=.  Unknown fields are errors.

=apply -n= prints one line per declared record:

#+begin_example
UPDATE web-origin: A www 192.0.2.10 -- adopt the identical unmanaged record
OK mail: MX @ mail.example.com -- matches
CREATE api: A api 192.0.2.11 -- no such record
#+end_example

Planning rules, in order: declared records must not collide; a record with
the key's ownership comment is updated in place (a move needs a free
destination); otherwise an identical unmarked record is adopted; otherwise a
record is created, provided a CNAME stays alone at its name and a new record
joins an existing set of its type only with =allow_multiple=.  Names ignore
ASCII case; values compare exactly.

* Safety

- The API key lives only in =key_file=: absolute, regular, not a symbolic
  link, mode 0400 or 0600, one line of printable ASCII.  It never appears in
  a command argument or the environment, and is sent only to Bunny.
- Every write is preceded by a zone snapshot (file 0600, directory 0700)
  and followed by a fresh read and verification.  Updates keep the record's
  ID and all its other Bunny settings.
- Writes are never retried or rolled back.  Do not run two writers against
  one zone at once.
- On SmartOS, when =SSL_CERT_FILE= is unset, pkgsrc's CA bundle is trusted.
  TLS verification is never disabled.

* Development

#+begin_src sh
gmake self-check    # checksum, compile, shellcheck, example, tests, manual
gmake checksum      # after reviewing a change to bunnydns.py
#+end_src

=bunnydns.py= reads top to bottom: constants, settings, records and
properties, the API key, the Bunny client, planning (pure functions), the
commands, and =main()=.  Exit status is 0 on success, 1 on error, 2 on a
usage error, and 130 when interrupted.

The =unittest= suite in =tests/= never contacts Bunny or changes the host:

- =test_planner.py=: the planning and output functions.
- =test_commands.py=: every command against =support.FakeBunny=, a stateful
  fake API on 127.0.0.1 with pagination, a decoy zone, and fault switches.
- =test_api.py=: the client, API errors, and signals.
- =test_inputs.py=: records, properties, settings, the key file, =init-key=.
- =test_makefile.py=: staged installs with mock =uname=, =zonename=, and
  package managers.

Tests reach the fake API through =main(api_base_url=...)=, which accepts only
Bunny's URL or a loopback address; the command line cannot redirect the key.
