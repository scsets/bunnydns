* Verdict

=dns_bunny.sh= (v0.4.0, 699 lines) is a careful, well-documented POSIX shell
reconciler.  Its use of the Bunny API matches the official documentation
exactly (endpoints, HTTP methods, the =AccessKey= header, the numeric record
type enum, and the =Comment= field used for ownership).  The security posture
is good: the API key never appears on a command line, key files are protected
and validated strictly, mutations are planned, gated on conflicts, backed up,
and re-verified.

Two defects should be fixed before relying on the tool on macOS, and a few
smaller items are worth addressing:

- *HIGH* - The Darwin key-mode branch (=stat -f '%Lp'=) breaks when GNU
  coreutils =stat= precedes BSD =stat= on =PATH=, which is common with
  Homebrew coreutils.  On this machine it breaks every online command and
  fails 27 of 45 offline checks.
- *MEDIUM* - =build_plan= runs its loop in a pipeline subshell, so =die=
  inside the loop does not abort the script; an internal failure can produce
  a partial plan that =plan= reports as clean.
- *LOW/NIT* - A handful of portability, wording, and metadata nits detailed
  in [[*Findings]].  Three findings were corrected after =counter-review.org=
  verified them against the sources: L1 and N3 are withdrawn, N1's proposed
  fix was invalid shell syntax, and N4's jq floor is 1.6, not 1.5 (see
  [[*Corrections from counter-review.org]]).

Everything else verified clean, including the full offline test suite once
the =stat= issue is removed from the environment.

- =gmake test= with =PATH=/usr/bin:/bin:/opt/homebrew/bin=: all 45 DNS checks

** Platform scope

Verification was performed on macOS (Darwin, =/bin/sh= = bash 3.2.57),
with additional shell checks under =dash=, =bash --posix= (5.x), and =ksh=.
The Linux and SunOS branches were verified against documentation only, not
on live hosts.  No live Bunny account was used; API behavior is verified
against the published reference and the offline mock.

* Verified against documented APIs

- Record type enum (0 A, 1 AAAA, 2 CNAME, 3 TXT, 4 MX, 8 SRV, 9 CAA, 10 PTR,
  12 NS, 13 SVCB, 14 HTTPS, 15 TLSA): the =type_id= map in =normalize_config=
  and the =type_name= map in =cmd_list= match the official enum exactly,
  including the exclusion of Redirect/Flatten/PullZone/Script types.
- Add record: =PUT /dnszone/{zoneId}/records= with =AccessKey= header; body
  fields =Ttl, Value, Name, Weight, Priority, Flags, Tag, Port, Disabled,
  Comment= are all documented fields.
- Update record: =POST /dnszone/{zoneId}/records/{id}=.
- Delete record: =DELETE /dnszone/{zoneId}/records/{id}=.
- List zones: =GET /dnszone= with =page=, =perPage= (range 5-1000; the script
  uses 1000, valid), and =search=.
- Zone document: =GET /dnszone/{id}= returns =Domain= and a =Records= array
  whose members carry =Comment= and =Disabled=, which the ownership model
  depends on.
- SmartOS: =stat -c '%a'= is supported by the illumos =stat(1)=
  (=--format=, =%a= octal permission bits).

* Findings

** H1 - Darwin mode check depends on which =stat= is first on PATH

*Severity*: HIGH.  *Location*: =file_mode()=, lines 166-172 (and the same
helper in =tests/test_dns_bunny.sh= lines 87-93).

On macOS the script runs =stat -f '%Lp' "$1"=.  With Homebrew coreutils
installed and =gnubin= on =PATH= (standard setup), =stat= resolves to GNU
coreutils stat, which interprets =-f= as =--file-system= and then treats
=%Lp= as a file name:

#+begin_example
stat: cannot read file system information for '%Lp': No such file or directory
dns_bunny.sh: cannot inspect Bunny API key file
#+end_example

Impact: every online command (=check=, =list=, =plan=, =apply=, =verify=,
=prune=) dies at key-file inspection, and the offline suite fails 27 of 45
checks on such machines (every check that reaches =load_api_key=).  The
failure message is misleading: the key file is fine, the =stat= flavor is
not.

Fix: on Darwin, call the BSD stat that macOS always ships at a fixed path:

#+begin_src sh
file_mode() {
  case $(uname -s) in
    Darwin) /usr/bin/stat -f '%Lp' "$1" ;;
    Linux|SunOS) stat -c '%a' "$1" ;;
    *) die "cannot inspect key permissions on this operating system" ;;
  esac
}
#+end_src

Apply the same change to the test helper so the suite itself does not fail
on machines with coreutils on =PATH=.

** M1 - =die= inside the =build_plan= pipeline does not abort the script

*Severity*: MEDIUM.  *Location*: =build_plan()=, lines 335-436.

The loop is fed by a pipeline:

#+begin_src sh
jq -c '.[]' "$DESIRED_FILE" | while IFS= read -r db_desired; do
  ...
  append_action ... || die ...
done
#+end_src

A pipeline runs the loop in a subshell, so =exit= (=die=) only terminates
the subshell.  The main shell never checks the pipeline status and continues:

#+begin_example
$ sh /tmp/pipe_repro.sh
DIED: boom on a
main shell continues after loop; pipeline status=1
#+end_example

Impact: if =append_action= (jq failure, unwritable plan file, disk full)
fails mid-plan, =cmd_plan= prints a partial plan and exits 0, and
=cmd_apply= may count fewer mutations than declared.  =apply= is partially
protected by the post-apply re-verification, but =plan= can report a clean
result for a broken plan.  The subshell also discards loop variables, which
is latent fragility (nothing currently depends on them).

Fix: materialize the desired lines in a temp file and redirect the loop from
it, keeping the loop in the main shell:

#+begin_src sh
jq -c '.[]' "$DESIRED_FILE" >"$DESIRED_LINES" || die "cannot prepare desired records"
while IFS= read -r db_desired; do
  ...
done <"$DESIRED_LINES"
#+end_src

(Add =DESIRED_LINES=$WORK_DIR/desired.ndjson= in =make_work_dir=.  The same
pipe pattern does not occur elsewhere: =apply_actions= and =cmd_prune= both
redirect from a file, which is correct.)

** L1 - =Type= in update bodies is documented (withdrawn)

*Severity*: none (withdrawn).  *Location*: =record_body()=, lines 467-473.

This finding is withdrawn.  The official
[[https://bunny.net/docs/api-reference/core/dns-zone/update-dns-record][Update DNS Record reference]]
includes =Type enum<integer> | null= in its request-body schema, with the
same 0-15 numeric enum the script uses; only the generated code examples
omit the field.  Sending =Type= from the single canonical =record_body= is
therefore documented behavior, and splitting the builder per method would
add complexity without evidence of benefit.  No change to the script.

** L2 - =replace= is delete-then-create, not atomic

*Severity*: LOW (accepted risk).  *Location*: =apply_actions()=, lines
488-493.

If the create after the delete fails, the old record is gone.  This is
explicitly documented in =dns_bunny.1= and =README.org= (the backup is the
recovery reference), so the behavior is intentional and disclosed.  Keep as
is; consider mentioning the risk in the =plan= output for REPLACE actions.

** L3 - Zone fetched before mutation is a snapshot; concurrent editors race

*Severity*: LOW (accepted).  *Location*: =cmd_apply()=.

There is a TOCTOU window between =fetch_zone= and the API mutations.  The
post-apply re-fetch and clean-plan requirement detect divergence rather than
prevent it.  Acceptable for an operator-driven tool; the README could state
the assumption that no other party edits the zone during =apply=.

** L4 - Post-apply conflict wording

*Severity*: LOW.  *Location*: =verify_plan_is_clean()=, lines 500-503.

=verify_plan_is_clean= counts every non-=ok= action, including =conflict=,
and reports "N DNS record(s) do not match the declared state".  A conflict
after apply is not a mismatch; the message misleads.  Consider counting
conflicts separately or rewording.

** N1 - Printable-ASCII pattern: keep the current spelling; do not use a bare space

*Severity*: NIT.  *Location*: =validate_api_key()=, line 178.

This finding is corrected: the review's original suggestion, =*[! -~]*=, is
invalid shell syntax because the unquoted space terminates the pattern word.
Verified syntax errors under macOS =/bin/sh= (bash 3.2), =/bin/bash=,
Homebrew Bash, =/bin/ksh=, and =/bin/zsh=:

#+begin_example
syntax error near unexpected token `-~]*'
#+end_example

The current =*[!\ -~]*= is correct under the script's forced =LC_ALL=C=:
with that locale, every shell tested (bash 3.2, bash 5, ksh) accepts
printable input and rejects control bytes.  The =LC_ALL=C= guard is
load-bearing and must stay.  If the backslash-inside-brackets spelling is
considered too subtle, the tested alternative is the POSIX character class:

#+begin_src sh
*[![:print:]]*)
#+end_src

which behaves identically under =LC_ALL=C= in all shells tested.  Keep the
separate leading/trailing-space check as is.

** N2 - Version string duplicated

*Severity*: NIT.  *Location*: =usage()= line 37; =tests/test_dns_bunny.sh=
lines 178, 181.

"0.4.0" is hardcoded in the usage text and asserted in the tests; the header
and =VERSION= hold it too.  A version bump must touch four places.  Use
=printf '%s %s\n' "$PROGRAM" "$VERSION"= in =usage= and derive the test
expectation from the script (=... | sed -n 's/^VERSION=//p'=) or accept the
manual sync as a documented step.

** N3 - Metadata block style follows the repository convention (withdrawn)

*Severity*: none (withdrawn).

This finding is withdrawn.  The repository's ordered native-comment
metadata block (=Filename=, =Description=, =Author=, =Copyright=, =Created=,
=Version=, =Last-Updated=, =Update #=) is the established convention across
the script, the manual, the README, the Makefile, and the tests.
=README.org= follows the same field sequence with shell-style comments, and
date-only stamps are the established doc-file style.  The review's
recommendation to convert to =#+FILENAME:=-style Org keywords and full
date-time stamps is not supported by project practice.  No change.

** N4 - jq floor is 1.6, not 1.5 (corrected)

*Severity*: NIT.  *Location*: =validate_config()=, line 104.

Corrected: the validation filter calls uppercase =IN(...)=.  The
[[https://jqlang.org/manual/v1.6/][jq 1.6 manual]] documents =IN(s)= and
=IN(source; s)=; the [[https://jqlang.org/manual/v1.5/][jq 1.5 manual]] does
not document =IN= at all.  Every other feature used (=ascii_upcase=,
=startswith=, =--slurpfile=, =//=, =?=) exists in 1.5, so =IN= sets the
floor at 1.6.

The README and manual should say =jq 1.6 or newer=.  If runtime enforcement
is desired, evaluate a tiny =IN= expression rather than parsing a
vendor-specific version string.

** N5 - SIGKILL leaves the key-bearing temp header behind

*Severity*: NIT.

The cleanup trap removes =WORK_DIR= on normal exit and common signals, but a
SIGKILL leaves the 0600 header file and 0700 directory behind in =TMPDIR=.
Acceptable residual risk (the dir is 0700, the file 0600); the README's
"temporary request data is removed at exit" could note the SIGKILL caveat.

** N6 - Man page omits signal exit status

*Severity*: NIT.

=dns_bunny.1= documents exit 0 and 1; the script exits 130 on HUP/INT/TERM.
Add one line to EXIT STATUS.

* What checked out clean

- *API conformance*: endpoints, methods, headers, type enum, and record
  fields all match the official reference (see [[*Verified against documented APIs]]).
- *Key hygiene*: key never on argv; copied into a 0600 header file inside a
  0700 temp dir; curl config 0600; =umask 077= before secrets; key file must
  be a regular file, mode 0400/0600, exactly one line, printable ASCII; no
  clobbering with =set -C= in =init-key=; terminal echo disabled and restored
  (including on traps); refuses =$HOME= as key directory.
- *Mutation safety*: =plan= and =apply= both refuse on conflicts; =apply=
  backs up the zone, applies only recorded actions, re-fetches, rebuilds the
  plan, and requires a clean plan; =prune= backs up and is scoped to the
  owner's comment prefix; same-second backup collisions are refused.
- *Reconciliation semantics*: ownership via unique comment
  (=managed-by:OWNER; key=KEY=); adoption of exact unmanaged records is
  metadata-only (DNS answer unchanged); CNAME exclusivity is enforced even
  with =allow_multiple=; duplicate keys and duplicate ownership comments are
  conflicts; identity changes are planned as REPLACE and documented as
  non-atomic.
- *Shell discipline*: POSIX-only constructs, =db_= prefixed variables
  instead of =local=, =set -u=, =LC_ALL=C=, no bashisms; =shellcheck= clean;
  =sh -n= clean.
- *Defense in depth*: cleanup trap guards its path before removing;
  =find_zone= requires exactly one match and validates the zone id;
  =fetch_zone= validates the zone document shape; error paths use
  =die= consistently (outside the M1 pipeline case).
- *Tests and docs*: the offline suite (45 + 20 checks) exercises planning,
  adoption, creation, replacement, verification, owner-isolated pruning,
  backups, mode branches, and CNAME conflicts, and passes once the =stat=
  environment issue is removed; man page and README accurately describe the
  behavior, including the non-atomic replacement caveat and the owner
  isolation rules.
- *Metadata*: script/man headers follow the required field sequence;
  version 0.4.0 is consistent across script, usage, man page, README,
  Makefile, and tests; created/last-updated weekdays are correct.

* Corrections from counter-review.org

=review.org= was counter-reviewed in =counter-review.org=.  Every contested
disposition was re-checked against the same sources with fresh fetches and
reproductions; the counter-review is accurate on all four points:

- L1 withdrawn: the official [[https://bunny.net/docs/api-reference/core/dns-zone/update-dns-record][Update DNS Record]] schema does list =Type enum<integer> | null=; only the generated examples omit it.
- N1 corrected: the review's proposed =*[! -~]*= is a syntax error in every
  shell tested (macOS =/bin/sh=, =/bin/bash=, Homebrew Bash, =/bin/ksh=,
  =/bin/zsh=); the existing =*[!\ -~]*= is correct under =LC_ALL=C=, and
  =*[![:print:]]*= is a verified equivalent alternative.
- N3 withdrawn: the native-comment metadata block is the repository
  convention; date-only stamps are the established doc-file style.
- N4 corrected: the jq floor is 1.6 because of uppercase =IN(...)=, which
  jq 1.5 does not document.

The counter-review's extensions are also adopted as implementation notes
for the fixes: guard every jq command substitution in =build_plan= (empty
results can otherwise reach numeric tests and comparisons silently), add a
GNU-=stat=-first Darwin regression test, and keep an independent literal
version assertion in the test suite rather than deriving it from the
script.
